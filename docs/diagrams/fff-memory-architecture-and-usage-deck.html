Predecessor Pitfalls (Go + LibSQL + Embeddings)

Infrastructure at Query Time

  • Fragile write path: Depended on a LAN embedding server; when down, zero rows stored.
  • Silent failures: Cosine similarity threshold (0.7) silently dropped valid notes.
  • Tool surface sprawl: 6 tools across 4 duplicate type representations.
  • Binary bloat: 52MB of committed binaries & dead vector code accumulated.

The fff-memory Paradigm (Rust + fff + rmcp)

Semantic Write, Lexical Query

  • Zero-network writes: Atomic file writes that always succeed, even with index down.
  • Microsecond search: Embedded fff lexical search with explainable match reasons.
  • 5 MCP tools: Minimal, ergonomic surface preventing agent fumbling.
  • Files as source of truth: Human-inspectable Markdown + Obsidian compatible.

Design Constraints

5 Non-Negotiable Invariants

  • 1. Files are Source of Truth: Index is a disposable cache rebuildable in one scan.
  • 2. Write Path Never Fails: Zero network and zero index dependencies on write.
  • 3. Exactly 5 MCP Tools: Focused surface; agents fumble wide tool suites.
  • 4. Token Economy First: Snippet-first retrieval strictly shaped by byte budget.
  • 5. Explainable & No Silent Empties: Every result carries a "why"; misses explain what was tried.
Why Token Economy?

The context window is the scarcest resource. Returning 5 whole raw markdown files wastes thousands of tokens.

Load-Bearing Field

The Alias Discipline

The aliases field is the direct semantic-search replacement. The LLM generates synonyms and alternate phrasings at write time so future lexical search succeeds under varied vocabulary.

  • Rule: Minimum 2 aliases required; aim for 3–6.
  • Vocabulary of Questions: Write aliases using terms the user will actually query, not rewordings of the title.
  • Matched Rationale: Retrieval returns exact alias matches in the why explanation field.
Example Query Scenarios
Title: Deploy pipeline uses GH Actions
User asks: "How do we ship code?"
→ Matches alias: 'shipping'

User asks: "What is our CI/CD setup?"
→ Matches alias: 'CI/CD'

Filesystem Hierarchy

Namespaces as Folders

Memories live in nested directories under the memory root. The handle linehaul/tms/auth directly maps to linehaul/tms/auth.md on disk.

  • XDG Default: ~/.local/share/fff-memory/
  • Project Root: .memory/ with --project flag
  • Git Friendly: Commit the directory to track memory history & team sync.

Reserved System Folders

.index/

Contains LMDB frecency state & access.log. Disposable cache; automatically gitignored.

.archive/

Where expired notes or soft-forgotten memories are moved. Excluded from default search.

Update Mode: Append (Default)

Augmenting Memory

When dedup detects an existing note and mode: "append" is selected:

  • Preserves original note body.
  • Appends a dated addendum section with new learnings.
  • Unions existing aliases & tags with new inputs.
  • Updates updated: YYYY-MM-DD timestamp.

Update Mode: Replace

Superseding Memory

When the new state completely replaces obsolete knowledge:

  • Replaces the entire markdown body with the new fact.
  • Unions aliases and tags to retain query discovery.
  • Retains original created date while bumping updated.

Explainable Math

Scoring & Frecency Formula

  • Normalized Match Score: Base score normalized to 0.0 ..= 1.0.
  • Both-Stages Bonus: Notes matching in both filename and content receive a ranking bonus.
  • Frecency Multiplier: Calculated from access.log:
    Frecency = 1.0 + (reads + 0.25 * search_hits) / 30_days
  • Type Boosts: Architectural decision and preference slightly outrank raw session-summary notes.
Explainable "Why" Line

Every result tells the agent exactly why it was surfaced:

"why": "alias:shipping +frecency(3r+8s/30d)"

No black-box embeddings — agents understand if the match was in a title, tag, alias, or body line.

Spec 05 — Lifecycle

Access Logging & Decay

  • Append-Only Log: .index/access.log records read and search-hit events.
  • Reinforcement: Frequently read notes receive a frecency multiplier bonus during ranking.
  • Decay Identification: Notes unaccessed after 30 days are flagged as decaying.
  • TTL Expiry: Notes with expires: YYYY-MM-DD past date are candidates for cleanup.
Doctor Sweep Operations
1. Archive Expired:
Moves notes past TTL into .archive/.
2. Broken Link Prune:
Detects dangling wikilinks.
3. Reindex Cache:
Wipes & rebuilds .index/ from disk Markdown in one fast scan.
